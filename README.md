# hyeseongkit

여러 AI 서비스(Claude / Claude Code / Codex / Antigravity / 로컬 모델)를 오가며 **하나의 작업을 이어서** 하기 위한 개인용 CLI 허브. 첫 번째 기능은 **세션 영속화**다.

> **상태: 허브·CLI·Claude Code 어댑터 구현 완료, 배포 준비 중.**
> 볼트 렌더용 livesync-bridge는 이후 단계(P4)이고, 요약·의미 검색은 아직 없다.

## 문제

모델의 내부 상태는 원리적으로 이전할 수 없고, 대화 전사를 통째로 옮기는 것도 컨텍스트·비용 한계로 실패한다. 옮길 수 있는 것은 **증류된 상태**뿐이다. 다만 증류를 요약과 동일시하면 결정의 근거가 사라져 다른 툴에서 같은 논의를 반복하게 된다.

→ 결정·제약·식별자·할 일은 **원문 그대로** 남기고, 서사와 탐색 과정만 버린다.

## 구조

```
각 기기의 CLI / MCP / 슬래시 커맨드
        │  HTTP (사설망)
        ▼
   NAS 허브 ──▶ CouchDB (SSOT, append-only 이벤트 로그)
                    │
                    └─▶ 마크다운 렌더 ──▶ 세션 전용 Obsidian 볼트 (열람 전용)
```

- **SSOT는 DB 하나**다. 볼트는 사람이 읽기 위한 파생 뷰이며 되돌아 흐르지 않는다
- 모든 저장은 **append-only** — 요약이 원문을 덮어쓸 수 없는 구조
- 저장 전 **시크릿 마스킹은 fail-closed** — 실패하면 전송하지 않는다
- 세션 본문은 **저장 시 암호화**된다. 열람용 마크다운은 허브가 복호화해 내보내므로 Obsidian에서는 평소대로 읽힌다

## 설계 원칙

- **필요한 기능만 만든다** — 범용 프레임워크를 목표하지 않는다. 실제로 겪은 불편만 구현한다
- **벤더 의존성 최소화** — 툴별 차이는 어댑터로 격리한다
- **하나의 코어, 세 개의 표면** — CLI / MCP / HTTP가 같은 로직을 호출한다
- **오프라인 열화 동작** — 허브가 죽어도 작업을 막지 않는다
