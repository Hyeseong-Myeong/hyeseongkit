# Agent Rules

이 저장소에서 작업하는 모든 에이전트가 지켜야 할 규칙이다. `local-llm-setup` 저장소의 동일 파일에서 가져와 이 프로젝트 맥락으로 조정했다.

- **사전 동의 원칙:** 기존에 합의된 설정(결정 사항, 아키텍처, 배포 방식 등)을 기술적 이유로 수정하거나, **설정 변경 후 시스템(컨테이너 등)을 재시작/실행할 때에는 무조건 어떤 변화(코드/설정)가 있었는지 먼저 사용자에게 상세히 설명하고, 명시적인 동의(실행 승인)를 구한 뒤에만 실행 명령을 내릴 것.** (어떤 경우에도 사용자 몰래 백그라운드 재시작 명령어 임의 실행 금지)
- **문서 기반 작업 원칙:** 단편적인 대화 맥락만으로 임의 판단하여 작업하지 말 것. 항상 [`docs/session_persistence_design.md`](../docs/session_persistence_design.md)(기획서, 특히 §11 결정 표·§12 위험 표)와 [`docs/session_persistence_impl_spec.md`](../docs/session_persistence_impl_spec.md)(설계서)를 전체적으로 꼼꼼히 확인하고, 작업 전 누락된 부분이나 향후 재작업이 필요한 병목 지점을 미리 파악할 것. 의문이 생기면 임의 진행하지 말고 반드시 사용자에게 먼저 확인할 것. 이미 확정된 결정(D1~D29)은 근거 없이 재논의하지 않는다.
- **사용자 개입 대기 원칙:** 사용자가 직접 수행해야 하는 작업(예: `.env` 파일 수정, NAS·GitHub 설정 등)이 필요한 경우, 다음 단계로 넘어가지 말고 작업 내역을 명시적으로 안내한 뒤 사용자의 '완료' 응답이 올 때까지 대기할 것.
- **환경변수·고유값 원칙 (D28):** 모든 시크릿 키, 인증 정보, 내부 주소, 로컬 경로는 하드코딩을 금지한다. 저장소가 **공개**이므로 특히 엄격히 지킨다 — 문서·코드·워크플로에는 `<PLACEHOLDER>` 형식만 쓰고, 실제 값은 각 기기의 `.env`에만 존재한다 (규약: [설계서 §0-3-1](../docs/session_persistence_impl_spec.md)). 에이전트는 사용자의 실제 `.env` 파일에 절대 접근(Read/Write)해서는 안 된다. 새로운 환경변수가 필요하면 반드시 `.env.example`에 키(Key)만 추가(`KEY=""`)하고, 실제 값 입력은 사용자에게 안내하여 사용자가 직접 `.env`에 입력하도록 한다.
- **Git 커밋/푸시 원칙:** 명시적인 사용자 지시가 없이는 절대로 커밋(commit), 푸시(push), 혹은 PR(Pull Request) 명령어를 단독으로 실행하지 마십시오. **push 직전에는 항상 diff와 커밋 이력을 재검토해 실제 IP·경로·자격증명이 섞여 들어가지 않았는지 확인**한다 — 공개 저장소이므로 한 번 push되면 되돌리기 어렵다. `main`은 Ruleset 보호 대상이 될 수 있으므로 항상 브랜치 + PR로 작업한다.
- **디버깅 및 트러블슈팅 원칙:** 에러가 발생했을 때 맹목적인 재실행(Trial-and-Error)이나 터미널 명령어를 남발하지 마십시오. 반드시 가장 먼저 로그 파일을 확인하여 근본 원인을 파악하고, 증상만 회피하는 땜질식 처방(Band-aid Fix) 대신 코드 상의 근본적인 수정을 진행하십시오. **폴링 루프 금지** — CI·외부 상태를 sleep 루프로 기다리지 말고 사용자에게 완료를 알려달라고 요청한다.
- **Windows 인코딩 대응 원칙:** 콘솔 출력에 유니코드(한글)가 있으면 CP949 기본 인코딩으로 `UnicodeEncodeError`가 발생할 수 있다. 표준 입출력을 UTF-8로 강제하는 방식(예: `PYTHONIOENCODING=utf-8`, `sys.stdout.reconfigure`)으로 근본 해결하고, 이모지 제거 등 임시방편으로 넘어가지 않는다. 문서·파일은 UTF-8 BOM 없음 + LF, `.ps1`/`.bat`만 CRLF (`.gitattributes` 강제). 한국어 텍스트는 CLI 인자로 넘기지 않고 stdin/파일로 받는다 (설계서 §11-2, 기획서 R15).
- **아티팩트 및 임시 파일 정리:** 임시 테스트 결과나 로그 파일을 작업 디렉토리 최상단에 방치하지 마십시오. 세션 작업 상태·개인 인프라 정보가 섞인 파일은 `tmp/`(gitignore 대상)에 두고, 커밋 대상 문서와 분리한다.
